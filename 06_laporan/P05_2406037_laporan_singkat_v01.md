### A. Tujuan Praktikum

Tujuan praktikum pertemuan 5 adalah menyusun skenario use case berdasarkan kebutuhan sistem yang telah dibuat pada pertemuan sebelumnya.

### B. Dasar Teori

Use Case Scenario merupakan deskripsi langkah-langkah interaksi antara aktor dengan sistem untuk mencapai tujuan tertentu.

Skenario use case terdiri dari:

1. Nama use case.
2. Aktor.
3. Tujuan.
4. Deskripsi.
5. Skenario normal.
6. Skenario alternatif.
7. Skenario akhir.

Skenario normal menjelaskan alur interaksi yang berjalan sesuai harapan, sedangkan skenario alternatif menjelaskan kondisi lain ketika proses utama tidak dapat berjalan seperti biasa.

### C. Hasil Praktikum

Pada praktikum ini disusun tujuh skenario use case Sistem Informasi Akademik, yaitu:

1. SIA-UC07 Lihat Kalender Akademik.
2. SIA-UC08 Input Nilai Mata Kuliah.
3. SIA-UC09 Lihat KHS.
4. SIA-UC10 Kelola Data Mahasiswa.
5. SIA-UC11 Tambah Data Mahasiswa.
6. SIA-UC12 Ubah Data Mahasiswa.
7. SIA-UC13 Hapus Data Mahasiswa.

Setiap use case dilengkapi dengan aktor, tujuan, deskripsi, skenario normal, skenario alternatif, dan skenario akhir.

### D. Analisis

Berdasarkan hasil penyusunan skenario, terdapat beberapa aktor yang terlibat, yaitu:

- Civitas Akademika.
- Dosen.
- Mahasiswa.
- Admin Akademik.

Dosen memiliki hak untuk memasukkan nilai mahasiswa pada mata kuliah yang diampunya.

Mahasiswa dapat melihat Kartu Hasil Studi (KHS) berdasarkan nilai yang telah dipublikasikan.

Admin Akademik bertugas mengelola data mahasiswa melalui fungsi tambah, ubah, dan hapus.

### E. Kesimpulan

Berdasarkan praktikum pertemuan 5, dapat disimpulkan bahwa penyusunan skenario use case membantu menjelaskan proses interaksi antara aktor dengan sistem secara lebih terstruktur.

Dengan adanya skenario normal dan alternatif, proses yang dilakukan oleh sistem dapat dipahami dengan lebih jelas.
